# 能力矩阵与集成说明（rd-governor）

本文件把分散在 6 个领域技能与系统模块里的能力，集中成一张"需求 → 能力 → 调用方式"的地图，供 rd-governor 在两条工作流中按需编排。

---

## 1. 数据底座：`rd_db` 工具集

**机制**：系统已通过 `agent_runtime.py` 的 `registry.register(toolset="rd_db", ...)` 进程内注册自定义工具集，Agent 可直接查 `data/rd_expense.db`（SQLite），**零 subprocess、零终端**。

**可访问的业务数据（表）**（表名一律单数，完整 schema 见 `schema.md`）：
- `project`（研发项目）：名称、编号、状态、预算、阶段、负责人（manager）、边界类型、归集口径
- `expense`（费用记录）：金额、科目、阶段、资本化状态、发生日期、关联项目与人员
- `personnel`（人员档案）：姓名、部门、岗位、是否研发人员、工时费率
- `work_time`（工时登记）、`labor_cost`（人工费用总账）
- `equipment`（研发设备）、设备工时、折旧分摊
- `material_requisition`（原材料领用）、`outsourcing_contract`（委托外部研发）
- `evidence`（证据材料）、`risk`（风险预警）、`capitalization_review`（资本化审批）
- `organization`（组织）、`policy_rule`（制度规则）、`project_node`（项目节点）

**查询范式（给模型的指引）**：
- 优先用系统自动注入的「数据快照」（项目概览、科目分布、风险预警）。
- 需要明细时用 `rd_db` 工具执行参数化查询（如"近三年各项目费用按科目汇总""研发人员工时占比"）。
- 数据不足时明确说明缺哪个字段/记录，并列入"待补资料清单"。

## 2. 资本化判断（企业会计准则第6号）

**依据**：《企业会计准则第6号——无形资产》开发阶段支出资本化 6 条件，逐项判定：
1. 技术可行性（通过可行性论证/小试中试）
2. 完成意图（有明确完成并使用/出售意图）
3. 使用或出售能力（有市场/渠道/内部场景）
4. 未来经济利益（能产生经济利益）
5. 资源充足性（技术/财务资源支持完成）
6. 支出可靠计量（开发支出能按项目单独归集计量）

**输出**：每项"满足/不满足/证据不足" + 会计处理建议（费用化/资本化/暂资本化待测试）+ 需补底稿。

---

## 3. 预算与差异分析

**维度**：
1. 总体执行率 = 累计实际 / 总预算
2. 分类执行率 = 人员人工 / 直接投入 / 折旧摊销 / 其他费用 各占预算比
3. 时间维度：按月/季展示节奏，识别异常波动
4. 差异原因：重大差异（>10% 或超阈值）定性与定量解释
5. 预测与建议：预测完工预算，提节支/追加建议

**输出**：3-5 句核心结论 + 关键指标表 + 异常波动原因与跟踪建议。

---

## 4. 合规审查

**7 维度审查**：
1. 归集口径（研究阶段 vs 开发阶段，费用化/资本化）
2. 凭证完整性（发票/合同/领料单/工时/验收报告）
3. 人员人工（研发身份、工时占比、薪酬归集方法）
4. 直接投入（原材料/燃料动力/模具工装按项目分摊）
5. 折旧与摊销（设备折旧/软件摊销与工时/使用频率匹配）
6. 其他费用（会议/差旅/咨询/检测是否与研发相关）
7. 加计扣除口径（对照税务总局公告列可加计/不可加计）

**输出**：总体结论（合规/风险/无法判断）+ 问题点表（问题/金额/依据/整改）+ 不确定时列待补资料。
**特别提示**：`evidence_id` 为 None 的费用属高风险（缺证据）。

---

## 5. 报告大纲

**7 章结构（三套资料包的统一骨架）**：
1. 项目概述（背景/立项依据/技术目标/起止/负责人）
2. 组织与人员（团队构成/资质/工时分配）
3. 费用归集（人员人工/直接投入/折旧摊销/设计费/装备调试试验费/其他）
4. 资本化与费用化处理（依据与金额）
5. 证据链清单（立项/预算/合同/发票/领料/工时/验收）
6. 加计扣除计算（可加计金额/比例/期间）
7. 风险提示与整改建议

## 6. 证据链模块：routes_compliance

**真实落点**（已存在于系统，工作流 B 必须对接，不要只在对话产出）：
- `GET /evidence?pid=` 按项目查证据链
- `POST /evidence` 新增证据条目
- `GET /evidence/{pid}/export` 导出证据链 PDF
- `GET /risks` 风险预警
- 报表中心：研发费归集表、辅助账等

**集成动作**：工作流 B 在归集佐证后，调用证据链接口把每条证据（`pid` 维度）落库；完成一处项目即可导出 PDF 作为申报附件。

## 7. 自动化引擎：scripts/generate_package.py

**作用**：从 `rd_db` 抽取项目/费用/人员/工时 → 套 `references/templates/` 模板 → 产出三套资料包草稿与各制度骨架草稿。把"全自动化生成"做成可执行引擎，模型再润色定稿。

**运行方式（二选一）**：
- 用 `run_python` 工具集直接执行（推荐）：`exec(open('scripts/generate_package.py').read())` 并传入 `db_path`。
- 用 `file` 工具把脚本写出到 `output/`，再由系统 Python 运行（终端在 Agent 侧被禁用，故优先 `run_python`）。

**脚本设计**：函数式可导入（`extract(db)` / `render_context(...)` / `build_xxx(...)`），`__main__` 负责连库、读模板、写文件到 `output/`。

## 8. 交付形态：通用交付规则

- **首选**：SYSTEM_PROMPT「通用交付规则」——用户点名框架用对应框架真实代码写到 `output/`，由 `delivery_guard` 做语言识别 + 编译/语法校验 + 路径镜像。
- 制度/资料正式交付物建议 **Word/PDF/Markdown**，便于归档与打印。
- 单文件网页不是本系统的主交付形态。

## 9. 研发费用管理方法论底座：`references/rd-mgmt-methodology.md`

从外部「研发费用管理技能」完整吸纳，覆盖：
- 研发活动界定（5 条件 / 3 类型 / 4 形式 / 负面清单）
- 预算经费构成（费用化 15 项 + 资本性支出）
- 费用归集**三大口径对比**（加计 / 高企 / 会计）
- 研发支出科目设置（一/二级科目树）
- 费用归集流程（人员人工 / 直接投入 / 折旧摊销）
- 辅助台账管理（8 科目 × 4 形式）
- 研究阶段 vs 开发阶段区分、试运行销售（财会〔2021〕35号）
- 加计扣除 6 项费用 + 委托研发规则（境内/境外/关联方 80%）
- 高企认定 8 类费用归集
- R&D 投入统计（范围 / 指标 / 原则）
- 常见风险 8 类与合规建议

工作流 A / B 在涉及上述主题时直接引用本文件，避免口径漂移。
